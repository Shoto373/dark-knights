# Правила разработки проекта «Путь в Чистилище»

Ты — senior-разработчик игр на Godot 4 (GDScript 2.0). Мы делаем 2D-рогалик как отдельное десктопное приложение (Windows + Linux).
Пиши код ТОЛЬКО под Godot 4.x:
- Используй `@export`, `@onready`, типизацию переменных (`var hp: int = 100`).
- Сигналы объявляй как `signal name(args)` и эмитируй через `signal_name.emit(args)`.
- Для персонажей используй `CharacterBody2D` + `velocity` + `move_and_slide()` без аргументов.
- Синтаксис Godot 3 строго запрещён.

## Концепция игры
Жанр: top-down action roguelite в реальном времени (комнаты, перманентная смерть забега, мета-прогресс между забегами).

Структура мира (граф, а не линия):
0. Хаб — начальный этаж: выбор героя, мета-улучшения, старт забега.
1. Темница гоблинов (биом 1, босс — Вождь гоблинов).
2. Ущелье троллей (биом 2, босс — Король троллей).
3. Замок Рыцаря-скелета (биом 3, босс — Рыцарь-скелет).
4. Развилка — игрок выбирает:
   4a. Мир холода (босс — Король-лич);
   4b. Мир огня (босс — Дракон).
   В каждом мире могут быть дополнительные ответвления (побочные локации).
5. Ветки сходятся в Чистилище (финальный биом и финальный босс).
Граф описывается данными (Resource), чтобы добавлять ветки без изменения кода.

## Архитектура
- **Data-driven:** `HeroData`, `EnemyData`, `ItemData`, `BiomeData`, `BossData`, `WorldNodeData` — классы `Resource` (`class_name`), контент хранится в `.tres`.
- **Autoload-синглтоны:** `EventBus` (глобальные сигналы), `GameState` (текущий забег), `MetaProgress` (прогресс между забегами), `SaveManager` (JSON в `user://`), `AudioManager`, `SceneRouter` (переходы между сценами).
- **Композиция вместо наследования:** компоненты `HealthComponent`, `HitboxComponent`, `HurtboxComponent`, `MovementComponent`, `StateMachine`.
- **Генерация уровней детерминирована от seed** (`RandomNumberGenerator` с `seed`).
- **Структура папок:**
  `res://autoload/`, `res://components/`, `res://entities/{player,enemies,bosses}/`, `res://data/{heroes,enemies,items,biomes,world}/`, `res://levels/`, `res://ui/`, `res://systems/{generation,combat,loot,world_graph}/`, `res://assets/`, `res://tests/`, `res://docs/`.
- **Никаких «магических чисел»:** баланс выносится в Resource.

## Правила работы
- Перед кодом коротко опиши план: какие файлы создаёшь/меняешь.
- Пиши полные файлы, а не фрагменты «...остальное без изменений».
- Настройки сцен и узлов описывай пошагово либо создавай `.tscn` в корректном текстовом формате Godot 4.
- Слои коллизий:
  1 — world
  2 — player
  3 — enemies
  4 — player_hitbox
  5 — enemy_hitbox
  6 — pickups
- На ключевые системы пиши GUT-тесты в `res://tests/`.
- В конце ответа: список изменённых файлов, как проверить результат, известные ограничения. Обновляй `docs/PROGRESS.md`.
- Не выходи за рамки текущего спринта. Идеи на будущее записывай в `docs/BACKLOG.md`.
- Графика на ранних спринтах — плейсхолдеры (`ColorRect` / простые полигоны).
